### Hero H2 size unification (landing 30px vs inner 26px)
- **What:** `src/app/page.tsx:46` hero H2 is `text-3xl` (30px). Onboarding/dashboard headlines are 26px.
- **Why:** 14% size jump on the first navigation from landing.
- **Fix:** Change to `text-[26px]` to match the rest of the app, OR raise the inner pages to 30px (decide which is the spec).

### Login page redundant inline `fontFamily`
- **What:** `src/app/auth/login/page.tsx:80` sets `style={{ fontFamily: ... }}` inline.
- **Why:** `globals.css @theme inline` already maps `--font-sans` to Pretendard; `body` inherits. Inline override is duplicate.
- **Fix:** Delete the inline `style` prop.

### Dashboard taste-profile card radius drift
- **What:** `src/app/dashboard/page.tsx:307` taste-profile card uses `rounded-3xl` (24px). The 3 stats cards above it use `rounded-2xl` (16px).
- **Why:** DESIGN.md reserves `rounded-3xl` for hero/lg only. Taste profile is a data card.
- **Fix:** `rounded-3xl` → `rounded-2xl`.

### Dashboard header full-width vs BottomNav max-w-md
- **What:** `src/app/dashboard/page.tsx:234` header is full-width; `src/components/BottomNav.tsx:54` is `max-w-md w-full`. On viewports >448px the bottom nav is narrower than the header.
- **Why:** Visual inconsistency on tablet+.
- **Fix:** Either constrain dashboard root to `max-w-[375px]` matching the rest, OR widen BottomNav to match (depends on Phase 2 desktop strategy).

### Landing H1/H2 semantic order
- **What:** `src/app/page.tsx:45` makes "Kindy" the H1 at 18px. The actual page-defining headline at line 46 is H2 at 30px.
- **Why:** Semantic heading order reversed. Bad for SEO and assistive tech.
- **Fix:** Swap — page headline becomes `<h1>`, "Kindy" becomes `<p className="...">` or `<h2>`.

### Legacy player stray `md:text-lg` breakpoint
- **What:** `src/app/player/[videoId]/page.tsx:266` uses `md:text-lg`. No other page in MVP defines `md:` variants — there's no responsive system for them to plug into.
- **Fix:** Drop `md:text-lg` (or define a project-wide responsive system; mobile-only MVP says drop).

### `prefers-color-scheme: dark` block exists but no `dark:` variants
- **What:** `src/app/globals.css:17-22` sets `--background` to near-black on dark devices, but no page applies `dark:` Tailwind variants. On dark-mode iOS, violet-50 and gray-900 utility classes layer onto a near-black body — undefined visual result.
- **Why:** Either commit to dark mode or remove the block. DESIGN.md doesn't mention dark mode.
- **Fix:** Remove the block (defer dark mode to a future scoped feature) OR implement `dark:` variants across pages.
