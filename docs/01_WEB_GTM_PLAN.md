# Kindy 웹 우선 GTM 계획 — 4주 내 유료고객 20명

> 작성: 2026-06-17 · 목표: 앱 출시(App Store Kids 심사 등 장기)를 기다리지 않고 **웹 + 카카오**로 먼저 유료 고객 20명 확보.
> 결정(2026-06-17): MVP=완전 자동 셀프서브 지향 · 기한=4주 · 결제=카카오/토스 결제링크(수동) · 유입=도서관 키오스크 QR + 카카오 채널.

---

## 0. 한 줄 전략

**검증이 끝난 두 자산(AI 영상 파이프라인 · GACS-3 엔진)을 iOS 앱이 아니라 웹에 먼저 얹어, "우리 아이만을 위해 매주 진화하는 영상 모험"을 셀프서브로 체험시키고, 도서관 데모와 카카오 채널로 4주 안에 첫 20가구를 유료 전환한다.**

핵심 차별점은 그대로다 — 같은 커리큘럼을 모두에게 주는 학습지/앱과 달리, Kindy는 *이 아이*의 반응(완주·재시청·응답)에 맞춰 다음 영상이 자동으로 더 잘 맞게 생성된다. 이걸 웹에서 가장 빠르게 증명하는 게 이번 스프린트의 전부다.

## 1. 짚고 갈 한 가지 긴장 (중요)

"완전 자동 셀프서브"와 "4주"와 "결제 수동"은 그대로 다 만족시킬 수 없다. 그래서 **층을 나눈다.**

| 층 | 4주 안 목표 | 이유 |
|---|---|---|
| **아이 경험** | **완전 자동** (가입→맞춤 영상 시청→반응→다음 영상 자동 진화) | 이게 제품의 본질이자 데모 임팩트. 자동화 필수. |
| **영상 생성** | **자동 생성 + 휴먼 1일 1회 승인 게이트** | 가드레일(아동 배포 전 휴먼 검수)은 절대 못 깬다. 생성은 자동, *배포 승인만* 수동(하루 10분). |
| **결제·구독** | **수동 결제링크 + entitlement 수동 토글** | 20명 규모엔 가맹점 정기결제 셋업보다 결제링크가 빠르다. 자동화는 20명 검증 후. |

→ 즉 **"아이에겐 완전 자동, 운영자에겐 하루 10분 게이트 2개(영상 승인·입금 확인)"** 가 4주 현실판이다. 이 전제가 틀리면 알려달라 — 전체 일정이 바뀐다.

### 실시간 생성에 대한 오해 풀기
영상 1배치(16본)는 10~15시간이 걸린다. 아이가 버튼을 누른 *그 순간* 새 영상을 뽑는 건 불가능하다. 그래서 "자동 진화"는 이렇게 동작한다:

- **즉시 개인화 = 풀(pool)에서 선택.** 미리 만들어 둔 변형(테마/톤별)에서 GACS-3가 이 아이에 맞는 걸 *즉시* 고른다 → 가입 첫 순간부터 "나를 위한 것" 느낌. (앱의 ThemeSelector가 이미 하는 일)
- **진화 = 야간 자동 배치.** 그날 active한 아이별 반응을 읽어 좌표를 갱신하고, 드리프트가 생기면 *그 아이 전용* 다음 영상을 밤사이 자동 생성 → 휴먼 승인 → 다음 세션에 등장.
- 주 2회 세션 리듬과 정확히 맞는다. 실시간일 필요가 없다.

## 2. 재사용 자산 (이미 검증됨 → 새로 안 만든다)

| 자산 | 상태 | 웹에서의 역할 |
|---|---|---|
| AI 영상 파이프라인 (`kindy-app/pipeline/`) | 스모크 8단계 전부 통과 | 콘텐츠 풀 생성 + 야간 진화 배치 그대로 사용 |
| GACS-3 (`pipeline/gacs.py`, `gacs_sim.py`) | Python 구현 존재 | 웹 백엔드 워커가 직접 호출 (재구현 불필요) |
| PD 에이전트 (`kindy_pd_agent.py`) | GACS 좌표→프롬프트 조건화 검증 | 좌표 기반 자동 생성 핵심 |
| QA 게이트 (`qa_gate.py`) | 감정 역측정+비전 5축 검증 | 생성물 자동 채점 → 승인 큐 정렬 |
| season1 콘텐츠 (8~9화 스크립트) | `convert_season.py`로 269씬 변환 확인 | 1차 콘텐츠 풀의 원천 |
| Supabase 프로젝트 | 앱과 공유, 카카오 OAuth 준비됨 | 웹 인증·DB·스토리지 그대로 |
| 30년차 교수 창의력 커리큘럼 | `docs/curriculum-*.md` | 신뢰 카피 + 부모 가치 증명 |
| 도서관 키오스크 B2G 역량 | 앱 모드 존재 | 웹 데모 + QR 핸드오프 유입 |

> 즉, **새로 만드는 건 "웹 프론트 + 오케스트레이션 워커 + 어드민 승인 UI + 웹용 Supabase 스키마"** 뿐이다. 어려운 AI 부분은 이미 끝났다.

## 3. MVP 범위 (4주 안에 만드는 것 / 빼는 것)

### 들어가는 것
1. **카카오 로그인 + 가정 온보딩** — 아이 1명, 이름·나이·관심사 3개 입력 (GACS 초기 좌표 시드).
2. **맞춤 영상 플레이어** — 풀에서 선택된 이 아이용 영상 재생. `question_hold`에서 정지 → 간단한 탭 응답 → 완주/재시청 추적. **이게 GACS 반응 신호 캡처의 전부.**
3. **자동 진화 루프** — 반응 → 좌표 갱신 → 야간 생성 → QA 자동채점 → 승인 큐 → 다음 영상.
4. **부모 대시보드(최소판)** — "이번 주는 ○○ 모험" + 주간 진화 증거 1화면 (점수·비교 없음).
5. **결제 게이팅** — 1~2주 무료 → 3주차 구독 안내(결제링크) → 입금 확인 시 entitlement on.
6. **랜딩 + 유입 연결** — `/start` QR 랜딩, 카카오 채널, 베타 후기 사회증거.
7. **어드민 승인 큐** — 운영자가 하루 한 번 신규 영상 승인.

### 빼는 것 (Phase 2로)
- 게임 5종 웹 이식 (인-영상 탭 응답으로 반응 신호는 이미 확보 → 게임은 나중).
- 다자녀 프로필, 계절 테마팩, 화면 이탈 감지, 토스 정기결제 자동화, B2G 기관 모드.
- 네이티브 앱 출시 트랙 (병행 중단 아님, 단지 이번 4주의 크리티컬패스 아님).

## 4. 기술 아키텍처 (가장 빠른 길)

```
[웹 프론트]  Next.js + Supabase JS  (Vercel 배포)
   ├─ 카카오 로그인 (Supabase Auth)
   ├─ 영상 플레이어 (question_hold 정지·탭응답·완주/재시청 이벤트)
   └─ 부모 대시보드(진화 증거)
        │  reaction events
        ▼
[Supabase]  Auth · Postgres · Storage(영상·키프레임) · entitlements
        │  nightly read (active children + reactions)
        ▼
[오케스트레이션 워커]  Python cron  (기존 pipeline 호출)
   gacs.py(좌표갱신) → kindy_pd_agent → generate_* → qa_gate(자동채점)
        │  published=false 로 적재
        ▼
[어드민 승인 큐]  운영자 1일 1회 승인 → published=true → 아이 라이브러리 노출
```

- **프론트:** Next.js (또는 단순 React)+Supabase가 가장 빠름. 인증·DB·스토리지가 이미 Supabase에 있어 백엔드 신규 구축 최소.
- **워커:** `kindy-app/pipeline/`를 그대로 cron으로 호출. 신규 코드 = 오케스트레이션 글루뿐.
- **결제:** 코드 통합 0. "구독하기" → 카카오/토스 결제링크 → 입금 확인 후 운영자가 `entitlements` 플래그 토글. (20명까진 충분)
- **빌드 위치:** `eduvid` 레포 (웹), Supabase는 앱과 공유.

## 5. 4주 실행 로드맵

### Week 1 — 기반 + 콘텐츠 풀 시드
- [대표] Supabase **프로덕션 전환** (현재 127.0.0.1 로컬) + 카카오 OAuth 활성화.
- [개발] 웹 스캐폴드: Next.js+Supabase, 카카오 로그인, 가정 온보딩(아이 1명·관심사).
- [개발+대표] **1차 콘텐츠 풀 생성**: season1 핵심 2~3화 × 테마 3종 부분 배치 → 휴먼 검수 → Storage 업로드. (부분 배치 비용 ~$30~50, 풀 16본 아님)
- [개발] 결제링크 + `entitlement` 수동 토글 설계.
- **검증:** 웹에서 카카오 로그인 → 온보딩 → 영상 1편 재생 성공.

### Week 2 — 핵심 경험 (시청 + 반응 + 즉시 개인화)
- [개발] 영상 플레이어: `question_hold` 정지 → 탭 응답 → 완주/재시청 이벤트 Supabase 적재.
- [개발] 즉시 개인화: ThemeSelector 로직 이식/재사용 → 가입 즉시 맞춤 변형 선택.
- [개발] 반응 → `gacs.py` 좌표 갱신 배치 연결.
- [개발] 부모 대시보드 최소판(주간 진화 증거 1화면).
- **검증:** 반응이 좌표를 바꾸고, 다음 추천 영상이 달라지는 것 확인.

### Week 3 — 자동 진화 루프 + 결제 + 랜딩
- [개발] 야간 자동 배치 워커(active child별 생성→`qa_gate` 자동채점→승인 대기).
- [개발] **어드민 승인 큐**(하루 10분 휴먼 게이트).
- [개발] 결제 게이팅: 1~2주 무료 → 3주차 구독 안내 → 입금 확인 시 entitlement on.
- [개발] 랜딩페이지 + `/start` QR + 카카오 채널 연결 + 베타 후기.
- **검증:** "반응→야간 생성→승인→다음 세션 등장" 엔드투엔드 1회 성공.

### Week 4 — 유입 가동 + 20명 푸시
- [대표] 도서관 키오스크 데모 세팅(아이패드/갤탭 + Guided Access) → 현장 QR.
- [대표] 카카오 플러스친구 개설 → 영상 샘플·체험 링크 배포 → 상담→결제.
- [대표+개발] 베타 5~10가구 + 도서관 데모로 가입 유도, 무료체험→결제 전환.
- [개발] 가입→체험→결제 퍼널 추적, 매일 수치 리뷰·반복.
- **검증:** **유료 entitlement 20건.**

## 6. 유입·전환 퍼널

```
도서관 키오스크 데모 ─┐
카카오 채널/샘플 영상 ─┼─→ /start 랜딩 → 카카오 로그인 → 온보딩
지인·맘카페(보조)    ─┘        → 1~2주 무료 체험(완주·진화 체감)
                                 → 3주차 "이번 주도 새 모험이 준비됐어요" 안내
                                 → 결제링크(카카오/토스) → 입금 확인 → 구독 on
```

- **무료 체험을 미끼로**: 첫 1~2주 무료로 "내 아이가 영상에 반응하니 다음 영상이 더 잘 맞더라"를 *직접 체감*시키는 게 전환의 핵심. 정서/학습 강조 대신 "아이가 좋아하고 매주 새로워진다"로만 말한다(긍정-온리 원칙).
- **사회증거**: 베타 가정 진짜 후기 5~10개(현재 페이월은 샘플 플레이스홀더 — 교체 필요).
- **가격(결정 필요)**: 앱 기준 ₩25,000/월. 웹 초기엔 도입가(예: ₩19,000/월 또는 첫 달 할인) 검토 권장 — 20명 확보가 우선이므로 진입장벽↓.

## 8. 리스크 & 가드레일 (위반=중단 사유)

- **아동 안전**: 영상은 휴먼 승인 없이 아동에 절대 노출 금지. 자동 생성하되 `published=false` 기본 + QA 자동채점(코사인≥0.5·dark 금지·비전 평균≥7)으로 승인 큐 정렬.
- **긍정-온리**: 아이·부모 카피에 불안·죄책감·비교·재촉·점수·등급 금지. 아이 화면 AI/결제 노출 0.
- **법무(체험 단계 허용, 정식 유료 전 필수)**: 개인정보처리방침, 아동 데이터 정책(온디바이스·AI 미학습 명시), 결제 약관·환불 정책 실제 페이지 연결. 웹은 카메라 이탈감지 미포함이라 제22조의2 본인인증 부담은 낮음.
- **4주 일정 리스크**: 영상 플레이어 반응 캡처와 야간 워커가 크리티컬패스. 여기 막히면 콘텐츠 풀 선택(즉시 개인화)만으로 데모하고 진화 루프는 Week 4로 밀 수 있는 폴백 보유.
- **비용**: 콘텐츠 풀 부분 배치 ~$30~50 + 진화 분 active child당 소액. 풀 16본 배치($115~155)는 유입 검증 후 집행.

## 9. 대표가 직접 해야 할 일 (병렬 착수)

1. **Supabase 프로덕션 전환** (Week 1 선행 — 모든 게 여기 의존).
2. **카카오 플러스친구 채널 개설** + 비즈니스 인증.
3. **결제링크 발급** (카카오페이/토스 결제링크) + 환불·약관 페이지 초안.
4. **콘텐츠 풀 1차 배치 승인** (~$30~50) + 키프레임 휴먼 검수.
5. **캐릭터 IP 확정** (모델시트 A/B) — 데모 인상 좌우.
6. **도서관 데모 슬롯 섭외** 1~2곳 + 키오스크 단말 준비.
7. **베타 가정 5~10가구 섭외** (지인·교수 네트워크) — 후기·초기 전환의 씨앗.
