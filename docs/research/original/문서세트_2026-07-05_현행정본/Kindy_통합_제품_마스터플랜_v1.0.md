## 0. 경영 요약 — 시뮬레이션이 바꾼 세 가지 결정

결정론적 계획(엑셀 기본 시나리오)에 7개 핵심 변수의 불확실성 분포를 얹어 10,000회 시뮬레이션한 결과, 계획은 다음과 같이 수정된다.

**시뮬레이션 5대 발견** (방법론·상세: §6)

| # | 발견 | 수치 | 의미 |
|---|---|---|---|
| F1 | 스프린트 목표는 사실상 확정 | P(M2 유료≥20) = **100%**, 중앙값 62가구 | 스프린트의 KPI를 "20명"에서 "퍼널 5변수 실측"으로 공식 변경 |
| F2 | 생존·흑자는 견고 | P(흑자 ≤M18) = **96.6%**, P(현금<0) = **0%**, 현금 최저 P10 = 1.72억 | Seed 3억으로 충분. Pre-A는 가속 자금 |
| F3 | **M+9 1,000가구는 현 계획으로 2.8%** | 중앙값 M9 = 701, 1,000 도달 중앙값 = **M+11** | 계약 지연(0–3개월)과 퍼널 곱셈 효과가 결정론 모델(833)을 깎아먹음 |
| F4 | 가속 패키지로 복구 가능 | 4레버 적용 시 P(M9≥1,000) = **100%**, 도달 M+7 | 레버: 도서관 M9까지 22관·계약지연≤1개월·QR 7%·전환 50% (+조건부 마케팅 2배) |
| F5 | 콘텐츠 소진 위험은 **첫 코호트에 집중** | 가입 M1 코호트의 2개월 내 소진 확률 36–57%, M3+ 코호트는 ~0% | 스프린트 유료 20가구(=Pre-A 리텐션 표본)가 정확히 위험 구간에 있음 |

**이에 따른 3대 결정**

- **D1. Two-Track 자원 배분 70/30.** Track R(매출: 결제·계측·리포트·콘텐츠 플로어)에 개발 리소스 70%, Track P(제품: Story/Studio 파이프라인)는 30% + AI 에이전트가 수행. 두 로드맵(스튜디오 12주 / 스프린트 8주)은 §3의 단일 16주 타임라인으로 통합.
- **D2. 도서관 가속 패키지 착수 + Pre-A 윈도우를 M+9~M+12로 커뮤니케이션.** 가속의 지배 레버는 도서관 관수(CSO 풀타임 커밋 + 수의계약 표준 패키지). 마케팅 2배 증액은 **CAC 실측 ≤ ₩27,470 확인 후에만** 집행(LTV/CAC 3× 게이트). 투자자에게는 시뮬레이션 분포 자체를 데이터룸에 공개 — 정직성이 협상력이다.
- **D3. 콘텐츠 런칭 플로어 40 복원 (백서 D-5 원안 복귀).** 심플 28편 + Theme 변형(3종)으로 체감 40+ 확보, 인터랙티브 에피소드 투입을 M3→**M2로 조기화**(재생 등가 3×). 재무모델 콘텐츠 예산 160만→**180만원/월**로 수정(혼합 파이프라인: 심플 6 + 인터랙티브 2).

## 1. 제품 정의

**One-liner**: 도서관에서 발견하고 집에서 자라는, 우리 아이만의 AI 이야기 숲 — 아이는 모리와 이야기를 탐험하고, 부모는 아이가 어떻게 배우는지를 처음으로 본다.

| 항목 | 정의 |
|---|---|
| 대상 | 만 5–7세 아동 + 그 부모 (구매자=부모, 사용자=아동·부모 이중 구조) |
| 아이 제공 가치 | 검사 아닌 놀이 — 이야기 숲 탐험, 선택으로 달라지는 나만의 결말, 이름을 불러주는 모리 |
| 부모 제공 가치 | 점수·비교가 아닌 **관찰** — C6 성장지도, 근거 카드, 대화 힌트 (재결제 이유 = "점점 더 잘 이해한다") |
| 형태 | 아이: iOS 앱/도서관 키오스크 · 부모: 웹(eduvid) · 시스템: 멀티에이전트 제작 파이프라인 |
| 하지 않는 것 | 발달 진단·점수·또래비교(C6 문서 §2), 자동결제 다크넛지, 무한 자동재생, 아이 화면 내 AI 용어 노출 |

**제품 원칙 5** — ① 아이에게는 세계관 언어만, 부모에게는 관찰 언어만 ② 모든 인터랙션은 C6 행동 증거가 된다(측정 불가한 기능은 만들지 않는다) ③ 콘텐츠는 사람이 승인한 것만 아이에게 닿는다(HITL 3게이트) ④ 신뢰를 기능으로 구현한다(1탭 해지·D-3 알림) ⑤ 모델은 갈아끼워도 캐릭터와 데이터는 회사 자산으로 남는다.

## 2. 네 개의 루프 — 제품·사업이 돌아가는 구조

"루프로 동작"이 이 계획의 뼈대다. 네 루프는 서로의 입력이 된다: 학습 루프가 데이터를 만들고 → 성장 루프가 리텐션을 만들고 → 공급 루프가 콘텐츠 적합도를 올리고 → 그로스 루프가 신규 유입을 만든다.

| 루프 | 주기 | 흐름 | 북극성 지표 | 자동 트리거 → 액션 | 담당 |
|---|---|---|---|---|---|
| **L1 학습 루프** (아이) | 세션(20분) | 씨앗 선택 → 영상+선택(CP) → 게임/퀴즈 → 표현 → 씨앗→꽃 보상 → 다음 씨앗 추천 | 세션 완주율 ≥70%, 재시도 후 완료율 | CP 무응답 15s → 모리 기본 경로 / 완주율 급락 → 난이도·길이 조정 실험 | 앱 + GACS·C6 엔진 |
| **L2 성장 루프** (부모) | 주간 | 행동 로그 → C6 갱신 → 주간 리포트 → 열람 → 대화 힌트(오프라인 전이) → 결제 유지 | **리포트 열람률 ≥60%** (churn의 선행지표) | 미열람 2주 → 요약 푸시 변경 / 열람 직후 → 결제·추천 훅 | 리포트 API + CMO |
| **L3 공급 루프** (콘텐츠) | 일·주 | C6 수요 신호(축별 evidence 부족·선호) → 스토리팀장 브리프 자동 생성 → 제작 → HITL 승인 → 퍼블리시 → 추천 풀 | 축별 콘텐츠 커버리지(6축×주간 신선도), 소진 위험 <10% | 특정 축 evidence_count 부족 → 해당 axis 브리프 우선순위↑ / 신모델 벤치 통과 → 카나리 | Story·Studio Guild + 오케스트레이터 |
| **L4 그로스 루프** (사업) | 월 | 도서관 계약 → 키오스크 노출 → QR → 가정 전환 → 이용 실적 → **도서관 성과 리포트** → 재계약·인접 도서관 레퍼런스 → 신규 계약 | 운영 관수, 관당 월 신규 유료, 재계약률 | 관당 신규 <3/월 → 현장 이벤트 투입 / 분기 → 도서관 리포트 자동 발송 | CSO + CMO |

루프의 연결 규칙 하나가 전체 재무를 지배한다: **L2 열람률 → churn ≤22.9% → LTV/CAC ≥3× → Pre-A 트리거**. 따라서 백로그 우선순위 충돌 시 L2 관련 티켓이 항상 이긴다.

## 3. 통합 타임라인 — 16주 (M1–M4), Two-Track

기존 두 로드맵의 통합·조정: 스프린트(8주)는 **현재 자산(심플 에피소드+기존 앱)으로 매출을 만들고**, Story Studio(12주)는 병렬로 **차세대 리텐션 자산(인터랙티브·개인화)을 만든다.** 유일한 교차점 = W9–10 인터랙티브 파일럿을 유료 코호트에 배포(구독 6–8주차, churn 최고점에 "와우" 이벤트를 명중).

| 게이트 | 주차 | Track R (매출·런칭) — 70% | Track P (제품·파이프라인) — 30%+에이전트 | 게이트 통과 기준 (Exit Criteria) |
|---|---|---|---|---|
| **G0 게이트 클리어** | W1–2 | D-1 IP계약·D-4 PIPA 착수, eduvid 배포, Toss E2E, 퍼널 계측 5종, 기업부설연구소 설립, 가격표 반영 | 모리 3D 마스터 외주 발주, 조연 Tripo 생성, 골든셋 확정, fal 어댑터 스켈레톤 | 테스트 결제·환불 왕복 ✓ / 계측 이벤트 대시보드 라이브 ✓ / IP 계약 서명 ✓ |
| **G1 매출 스프린트** | W3–8 | 소프트런칭(2→3관) → W4 리포트 훅+결제 오픈 → paid 테스트 → **W8 유료 20+** · 콘텐츠 28편+Theme 변형(체감 40+) | Story Guild 가동 → "물방울" 분기 대본 HITL#1 승인(W5) → 키프레임·샷 생성 → **파일럿 인터랙티브 1편 완성(W8)** | 유료 ≥20 ✓ / 퍼널 5변수 실측 ✓ / 4주 유지율 측정 개시 ✓ / 파일럿 시사 통과 ✓ / 에피소드 원가 ≤ ₩50만 ✓ |
| **G2 리텐션 자산 배포** | W9–12 | 도서관 5→8관(가속 패키지 착수), 도서관 성과 리포트 v1 발송, CAC 실측으로 마케팅 증액 판단 | 분기 플레이어(웹) 배포 → 유료 코호트에 인터랙티브 파일럿 오픈, **L2 호명** 가동, 인터랙티브 2편/월 정례화 | 인터랙티브 시청 코호트 vs 대조군 4주 유지율 비교 데이터 확보 ✓ / 호명 개인정보 로컬 처리 검증 ✓ |
| **G3 시스템화·베타** | W13–16 | 베타 50가구(백서 Phase B 통합), Pre-A 데이터룸 v1(코호트·시뮬 포함), TIPS 신청 준비 | 오케스트레이터 v1(레지스트리·이벌·카나리·다이제스트), 에피소드 누적: 심플 40+·인터랙티브 4 | 리포트 열람률 ≥60% ✓ / 신모델 1개 카나리 실주행 ✓ / 월 churn 실측치 확보 ✓ |

자원 규칙: CEO-dev의 주간 계획에서 Track P 직접 코딩은 30%를 넘지 않는다 — 초과분은 Claude Code 에이전트 작업지시(§4.5 백로그의 오너=CC 티켓)로 전환하거나 다음 게이트로 이월한다. 이 규칙이 무너지면 매출 스프린트가 무너진다.

### 4.2 데이터 스키마 통합 맵 (Supabase/Postgres)

기존: children · library_videos · view_events · quiz_results · game_sessions · game_rounds · subscriptions/entitlements
마이그레이션 3개를 이 순서로 적용한다 — **001_c6_growth_map.sql** (C6 문서 §10.1 그대로: c6_axes, story_seeds, child_growth_profiles, recommendation_logs + 기존 테이블 컬럼 추가), **002_story_studio.sql** (스튜디오 플랜 §7 그대로: episodes, episode_nodes, shots, renders, model_registry, eval_runs), **003_commerce.sql** (신규):

```sql
create table consents (
  id uuid primary key default gen_random_uuid(),
  parent_user_id uuid not null,
  child_id uuid references children(id),
  consent_type text not null,          -- 'guardian_u14' | 'overseas_transfer' | 'sensitive_gacs'
  policy_version text not null,
  granted_at timestamptz not null default now(),
  revoked_at timestamptz, ip inet
);
create table payments (
  id uuid primary key default gen_random_uuid(),
  subscription_id uuid, toss_payment_key text unique,
  amount int not null, vat int not null, status text not null,   -- ready|paid|canceled|failed
  method text, receipt_url text, created_at timestamptz default now()
);
alter table subscriptions add column if not exists plan text default 'monthly',
  add column if not exists price_locked int,                      -- 얼리버드 락인가
  add column if not exists cancel_effective_at timestamptz,
  add column if not exists next_billing_notice_sent_at timestamptz;  -- D-3 알림 증적
```

## 6. 시뮬레이션 — 방법론·결과·계획 반영

**방법론**: 재무모델 v1.0의 기본 시나리오를 기준선으로, 7개 변수에 삼각분포를 부여해 10,000회 × 36개월 실행 — QR 스캔율 Tri(3,6,9%) · 가입율 Tri(35,45,55%) · 체험시작 Tri(50,60,70%) · 체험→유료 Tri(30,45,60%) · 월 churn Tri(15,25,35%) · CAC Tri(2.5,3.0,4.5만) · 관당 세션 Tri(800,1200,1600) + **도서관·B2G 계약 지연 0–3개월(균등)**. 가격·원가·인건비·B2G 단가는 엑셀과 동일. 콘텐츠 소진은 코호트별 신선 에피소드 수요 Tri(16,26,39편/월)·재시청 계수 1.3·인터랙티브 등가 3×로 별도 시뮬. 결과 차트: Kindy_시뮬레이션_결과.png.

**결과 요약**

| 지표 | P10 | P50 | P90 | 판정 |
|---|---|---|---|---|
| M+2 유료 가구 | 50 | 62 | 79 | P(≥20)=100% — 스프린트 확정 |

**가속 패키지 검증** (도서관 M9까지 22관 + 계약지연 ≤1개월 + QR 7% + 전환 50% + 마케팅 2배): P(M9≥1,000) = **100%**, 중앙값 도달 **M+7**, M9 P10=1,263. 기본 계획의 1,000 도달 중앙값은 **M+11**(M12 중앙값 1,208). → §0 결정 D2.

**콘텐츠 소진**: 가입 M3+ 코호트는 전 시나리오 소진 위험 ~0%. 위험은 M1–M2 코호트에 집중(2개월 내 36–57%) — 인터랙티브 조기 투입(M2)과 런칭 플로어 40(변형 포함)으로만 완화 가능. **파이프라인 증설(월 12편)보다 런칭 시점 재고가 결정 변수**라는 것이 핵심 발견. → 결정 D3.

**제작 용량**: 인터랙티브 1편 생성 wall-clock ≈1.3h(동시성 12) — 생성은 병목 아님. HITL 월 소요 270분 vs 검수 용량 2,400분 — 병목 아님. 실제 병목은 **선행 자산(캐릭터 바이블)과 첫 파이프라인 브링업**이므로 E7-1을 W1 발주. 혼합 원가 월 180만 → 재무모델 '가정' 시트 콘텐츠 원가 160만→180만 수정 지시(결론 불변: BEP +10가구 내외).

**엑셀(결정론) 대비 시뮬 중앙값이 낮은 이유** — 검토자 예상 질문: ① 곱셈 퍼널에서 비대칭 분포의 곱은 최빈값 곱보다 중앙값이 낮다(hero 시나리오 편향 제거 효과) ② 계약 지연 변수는 결정론 모델에 없던 하방 리스크다. 즉 격차(833 vs 701)는 오류가 아니라 **불확실성의 가격**이며, 이것이 시뮬레이션을 데이터룸에 공개하는 이유다.
