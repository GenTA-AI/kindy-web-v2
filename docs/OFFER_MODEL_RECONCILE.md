# 오퍼 모델 정리 (드리프트 해소) — 2026-07-01

> 배경: 사업 메모리의 오퍼("주 3편 그 아이용 맞춤영상 · 주 ₩5,000")와 현재 코드
> ("월 ₩25,000 · 공유 라이브러리+동물마을")가 갈렸다. 이 문서로 방향을 고정한다.

## 핵심 통찰: 두 축은 별개다
- **결제 축**(월/주, 금액)과 **콘텐츠 개인화 축**(공유/비스포크)은 독립적이다.
- 드리프트는 "둘 중 하나 고르기"가 아니다 → **결제는 월 구독 유지, 콘텐츠는 비스포크로.**

## 확정
1. **결제 = 월 구독 ₩25,000 유지.** 이미 구축됨(Toss 빌링키 + 정기결제 cron + 명시동의).
   주간 소액보다 리텐션·예측가능성·운영 단순성에서 유리. (검증 단계 가격은 대표가 조정 가능.)
2. **콘텐츠 = 비스포크 초개인화(불변핵심).** 아이의 **약점(struggleTool, 숙련 낮은 C6 도구)**을
   겨냥해 그 아이용 콘텐츠를 만든다. 공유 라이브러리는 콜드스타트/기본값으로 병행.
3. **생성 방식 = 20가구 콘시어지(대표 직접/감독).** 자동 생성·자동청구 아님. 약점 진단 →
   생성 브리프 → **운영자(대표)가 트리거·검수** → 그 아이 라이브러리에 편입. 비용($~7/편) 통제.

## 루프 구현 상태
```
진단 → 비스포크 생성 → 성장 증명
 ✅        🔨(지금)         ⬜
```
- ✅ 진단: `src/lib/game/learning-profile.ts` (숙련 기반 약점/조건).
- 🔨 비스포크: `learning-profile.struggleTool` → `bespoke-brief` → 운영자 게이트 생성(`/api/videos/bespoke`).
- ⬜ 성장: 주간 정성 서사("처음 해낸 것"), 점수 없이.

## 안전장치
- 생성 트리거는 **운영자 키(`KINDY_OPERATOR_KEY`) 게이트** — 임의 호출로 비용 폭발 방지.
- 아이당 진행중(queued/processing) 영상 있으면 재큐 안 함(중복 생성 방지).
