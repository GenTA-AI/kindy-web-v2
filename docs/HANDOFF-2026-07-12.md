## 0. 이 세션처럼 일하는 법 (대표 지시로 확립된 규칙)

- **보고 스타일**: 태스크 ID·계획 코드명을 맨몸으로 쓰지 않는다 — 항상 괄호로 설명 병기. 예: "t9(고전 극장 정본 개정)".
- **말은 결론부터**, 한국어로. 대표는 수치와 근거를 원함 — "왜"를 실측으로 증명해야 넘어간다.
- **실수했을 때**: 변명 없이 원인을 정확히 찾아 재발 방지 장치(린터/게이트/가드)까지 만들어 보고. (예: "문제가 어디였는지 정확하게 찾아", "qc가 왜 놓쳤는지도 체크해야해")
- **모든 수치 저장**: 생성·QC·게이트·인간 채점 전부 `mori-studio/data/experiments/`에 append-only JSONL로. 논문·데이터셋화 목적. 기각도 기록, "fooled"(심사 오판)도 기록.
- **구현 주체**: 코드 구현 기본은 Codex 워커, 같은 태스크 2회 스톨 시 Claude 폴백(게이트·리뷰 동일). 단, 대표가 세션에서 직접 시키면 그 세션이 구현.
- **워커 규칙**: .env/시크릿 출력 금지, 워커 빌드에서 유료 API 라이브 호출 금지.
- **kindy-web.v2 레포 규칙**(AGENTS.md): base=main, **main 직접 푸시 금지, DRAFT PR만**, 구현 전 docs/LESSONS.md 읽기(현재 사실상 빈 파일 — 함정 발견 시 `- YYYY-MM-DD: <mistake> -> <rule>` 형식으로 append), **Next.js 16은 훈련 데이터와 다르니 node_modules/next/dist/docs/ 확인** (async params/searchParams는 Promise — 반드시 await).
