# landing-price-claims: 가격 출처 단일화 + 지킬 수 없는 클레임 2건 제거
effort: high

## Goal

**표시 금액 = 청구 금액**을 만들고, 실제로 존재하지 않는 기능을 약속하는 문장 두 개를 지운다.

지금 실제로 청구되는 금액은 24,900원(`src/lib/subscription.ts`의 상수) 하나다. 그런데:
- **체크아웃 화면**이 "카드를 등록하면 첫 달 **25,000원**이 바로 결제돼요"라고 적어놓고 24,900원을
  청구한다. **같은 화면의 요금 카드는 24,900원이다.** 실가 결제를 받는 바로 그 화면의 표시가격 오류다.
- `/subscribe` 페이지 메타데이터도 "월 25,000원".
- 랜딩에 `?ks` 쿼리를 붙이면 "도서관 한정 월 ₩19,000" 배지가 뜨는데, **19,000원을 청구할 수 있는
  코드 경로가 없다.** 아무나 URL에 `?ks`를 붙이면 볼 수 있다.
- `SubscribeClient`가 가격 상수를 자기 파일에 중복 정의하고 있다.

그리고 대표가 제거하기로 결정한 클레임 2건(2026-08-03):
- **"영상이 아이의 이름을 부르며 시작합니다"** — 실제로 안 된다. TTS가 한글 이름을 오독한다
  (서윤아 → 서이다). 배달되는 큐레이션 영상은 아이 이름을 부르지 않는다.
- **"여섯 달이면 마흔여덟 편"** — 현재 제품 형태의 온타깃 재고는 1편이다.

**유지하는 것(건드리지 마라)**: 30년 교수 커리큘럼, 런던 수학 경력, 경쟁사 가격 비교표, 카톡 배송·
해지 문구, 14일 100% 환불 문구. 전부 대표가 유지하기로 결정했다.

## Scope

- `src/lib/subscription-pricing.ts` NEW 클라이언트가 안전하게 import할 leaf 모듈
- `src/lib/subscription-pricing.test.ts` NEW 아래 Deliverables 8의 단위 테스트
- `src/app/page.tsx` 랜딩 — ?ks 배지·이름 호명·48편
- `src/app/subscribe/SubscribeClient.tsx` 체크아웃 화면 문구·중복 상수
- `src/app/subscribe/page.tsx` 메타데이터 가격
- `src/app/first-story/page.tsx` 가격 문구가 있으면 여기도 단일 출처로

## Constraints
- **금액 하드코딩을 새로 만들지 마라.** 모든 표시 금액은 `src/lib/subscription.ts`의 상수(또는
  거기서 파생된 포맷 헬퍼)에서 온다. 문자열 안에 숫자를 직접 박지 마라.
- 정가 앵커(34,900원)와 얼리버드(24,900원)의 **관계는 유지**한다. 정가를 지우지 마라 — 의도된 앵커다.
- `?ks` 처리: 배지는 제거하되, **`?ks` 파라미터 자체(키오스크 QR 어트리뷰션)는 건드리지 마라.**
  `/start?ks=<token>` 경로와 `src/app/api/attribution/claim/route.ts`는 살아 있는 배관이다.
  랜딩의 **가격 배지만** 없앤다.
- `?ks`를 랜딩에서 더 이상 읽지 않게 되면 홈이 정적 렌더로 돌아갈 수 있다. 그렇게 되면 좋지만,
  **그걸 목적으로 다른 것을 리팩터하지 마라.** 자연히 그렇게 되면 핸드오프에 적어라.
- 대표가 유지하기로 한 클레임(교수·런던·비교표·카톡·14일 환불)을 **지우거나 약화시키지 마라.**
- `src/content/legal/*.md`를 수정하지 마라 — 약관·환불 정본은 법무 검토가 걸린 후속 미션이다.
- 고객 화면 문자열에 진단/평가/점수/등급/또래비교/발달지연/C코드/커리큘럼 용어 금지.
- 디자인·레이아웃을 바꾸지 마라. 문자열과 상수만 건드린다. 문장이 빠져 레이아웃이 어색해지면
  **최소한으로만** 조정하고 그 사실을 핸드오프에 적어라.

## Deliverables
1. 소스 전체에서 `25,000`/`25000`이 사용자에게 보이는 가격으로 남아 있지 않다
   (DB 기본값은 마이그레이션 영역이라 이 태스크 밖 — 발견하면 핸드오프에 적기만 하라).
2. `SubscribeClient.tsx`의 중복 가격 상수가 제거되고 `src/lib/subscription.ts`에서 import한다.
3. 체크아웃 화면의 "첫 달 25,000원" 문구가 실제 청구액과 일치한다.
4. `/subscribe` 메타데이터 가격이 실제와 일치한다.
5. 랜딩의 "도서관 한정 월 ₩19,000" 배지가 제거된다.
6. "이름을 부르며 시작" 취지의 문장이 랜딩에서 제거된다(개인화 섹션 전체를 지우는 게 아니라,
   **이름 호명 약속만** 걷어낸다. 남는 문장이 자연스럽게 읽히도록 다듬어라).
7. "여섯 달이면 마흔여덟 편" 취지의 수량·기간 약속이 제거된다.
8. 가격 표시가 단일 출처에서 온다는 것을 확인하는 단위 테스트(포맷 헬퍼를 만들었다면 그 테스트).
   `node:test` + `npx tsx --test`, 상대 import.

## Validation

```bash
npm run lint
npx next typegen && npx tsc --noEmit
npm test
npm run build
```

추가로 자체 확인하고 결과를 핸드오프에 붙여라(이 명령들의 출력이 비어 있어야 정상):

```bash
grep -rn "25,000\|25000" src/app src/lib --include=*.ts --include=*.tsx || echo "OK: no 25000 in src"
grep -rn "19,000\|₩19" src/app --include=*.tsx || echo "OK: no 19000 badge"
```

## Handoff requirements

최종 메시지 끝에: summary, files_changed, validation(명령어 + **실제 출력**, 위 grep 결과 포함),
risks, handoff_note.

`handoff_note`에 반드시:
- 제거한 문장의 **원문 그대로**와 대체한 문장(리드가 대표에게 보여줄 것이다).
- 가격이 표시되는 모든 위치의 최종 목록과 각각의 출처.
- 랜딩이 정적 렌더로 바뀌었는지 여부(빌드 출력의 해당 라우트 표시).
- 남아 있는 25,000원(DB 기본값 등)이 있으면 위치와 영향.
